4. BACKEND OVERVIEW
-------------------
* Packages:
  - com.bookmyplay.config (CORS, resource mapping, basic security configuration)
  - com.bookmyplay.controller (Handles HTTP requests and maps them to REST endpoints)
  - com.bookmyplay.dto (Request and Response data transfer objects)
  - com.bookmyplay.entity (JPA Database Entities)
  - com.bookmyplay.repository (JPA Repositories for database querying)
  - com.bookmyplay.service (Service interfaces and business logic implementations)

* Controllers:
  - AdminController (Basic dashboard statistics and user list retrieval)
  - AdminExtendedController (Detailed admin actions, venue approval, ticket management)
  - AuthController (Registration, login, reset password using captcha verification)
  - BookingController (Booking creation, rescheduling, user/vendor bookings)
  - CategoryController (Manage venue categories)
  - ContactSettingsController (Manage contact info settings)
  - CouponController (Validate and list coupons)
  - NotificationController (User/vendor notification queries)
  - PaymentController (Process payments and get history)
  - ReportController (Export booking and payment sheets)
  - ReviewController (Add and list ratings/reviews)
  - SlotController (Query and generate time slots)
  - SubscriptionController (Manage plans and approve/reject subscription payments)
  - UserController (Manage user profiles and upload profile photos)
  - VendorController (Retrieve stats for vendors)
  - VenueController (CRUD operations and search for venues)

* Services:
  - AdminService / AdminServiceImpl
  - BookingService / BookingServiceImpl
  - CategoryService / CategoryServiceImpl
  - ReviewService / ReviewServiceImpl
  - SlotService / SlotServiceImpl
  - UserService / UserServiceImpl
  - VendorService / VendorServiceImpl
  - VenueService / VenueServiceImpl
  - SubscriptionScheduler (Cron scheduler for tracking expiration dates of plans)

* Database Tables (MySQL):
  - users (Mapped to User.java)
  - venues (Mapped to Venue.java)
  - venue_images (Mapped to VenueImage.java)
  - bookings (Mapped to Booking.java)
  - reviews (Mapped to Review.java)
  - categories (Mapped to Category.java)
  - payments (Mapped to Payment.java)
  - slots (Mapped to Slot.java)
  - subscription_plans (Mapped to SubscriptionPlan.java)
  - vendor_subscriptions (Mapped to VendorSubscription.java)
  - support_tickets (Mapped to SupportTicket.java)
  - audit_logs (Mapped to AuditLog.java)
  - website_settings (Mapped to WebsiteSettings.java)
  - contact_settings (Mapped to ContactSettings.java)

* Relationships:
  - Booking: ManyToOne relation to User, Venue, Slot
  - Venue: ManyToOne relation to Category, OneToMany to VenueImage, OneToMany to Review
  - VenueImage: ManyToOne relation to Venue
  - Review: ManyToOne relation to Venue, ManyToOne relation to User

* Authentication, Roles, & Security:
  - Handled via custom manual checks in `AuthController.java` (using BCrypt for passwords).
  - User profiles (with role fields) are returned on successful login.
  - Roles: USER, VENDOR, ADMIN.
  - Security Config: Currently only contains a PasswordEncoder bean definition. Endpoints are unprotected, authorization checks are client-side or checked manually via query parameters.

12. DATABASE ISSUES
-------------------
- Mapped relationships use FetchType.LAZY inside entities but aren't always eagerly joined in queries, which may cause N+1 query problems.
- Use of `ddl-auto=update` in application.properties should be migrated to database version control tools (like Liquibase or Flyway) for production.

13. PERFORMANCE ISSUES
----------------------
- In-memory processing of counts/filters (e.g. calling `userRepository.findAll().stream().filter(...).count()` in `AdminServiceImpl`) which consumes server memory. This should be rewritten to JPA custom aggregate count queries.

14. UI/UX PROBLEMS
------------------
- Native alerts were globally overridden with SweetAlert2, which works great, but some UI layouts might have misalignments with custom dashboards if font sizes/margins differ.

15. CODE SMELLS
